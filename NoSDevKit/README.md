# NoSDevKit

開発者専用の BepInEx プラグイン。配布するアドオンには含めない。

## ホットリロード

ゲームを起動したまま `Scripts/*.cs` を保存すると、変更したメソッドの本体だけを差し替える（2〜3 秒）。

- 対応: メソッド・プロパティ・ラムダ・コルーチンの**中身**の変更
- 非対応（ログに「再起動が必要」と出る）: 型・メソッド・フィールドの追加/削除、シグネチャの変更、新しいラムダの追加
- 反映されない: static 初期化（起動時に実行済み）、ジェネリックなメソッド/型
- 既に呼び出し元へインライン化された小さなメソッドは、差し替えても古い動作のままになることがある
- ソースを元に戻すと、そのメソッドのフックも外れる

### 前提

ゲームに読み込まれているアドオン（`Addons/*.zip`）が、今のソースからビルドしたものであること。
ずれていると構造の差分として検出され、差し替えは行われない。

## 自動フリープレイ

起動すると、ローカルロビーの作成 → NoS のゲームモードをフリープレイに → ダミーの人数を設定 → ゲーム開始、まで自動で進む。

- ダミーは NoS の「ソロフリープレイ: ダミーの数」の仕組みで追加される（`NumOfDummies`、0〜23）
- カウントダウンは F1（クイックスタート）と同じく飛ばす。F1 と違ってダミーの追加は行われる
- `Role` に役職の内部名（例: `autocracy`）を書くと、開始後に自分をその役職にする。名前を間違えると、指定できる名前の一覧がログに出る
- 起動中（メインメニューが出るまで）に **Shift を押しっぱなし**にすると中止する
- NoS 側の設定（ゲームモード・ダミーの数）を書き換えるので、オンラインで遊ぶときはゲームモードを戻すこと
- 結果は `AutoFreeplay:` でログに出る

## ログ

BepInEx のログ（Unity の例外を含む）と NoS の NebulaLog.txt を、ゲームフォルダの `DevKit.log` に 1 つにまとめる。

- VS Code のタスク「NoS ログを見る」で色つき表示（`tools/Watch-DevKitLog.ps1`）。ゲームを再起動しても追従する
- コンパイルエラーは `パス:行:列` の形で出るので、ターミナルからクリックでその行に飛べる
- 警告・エラーと NoSDevKit の通知は、ゲーム画面の左上（NoS の DebugScreen）にも数秒表示する
- 起動時に大量に出る無関係なログは `[Log] IgnorePattern` で除いている
- 複数起動したときは 2 つ目以降を `DevKit.2.log` のように分ける（`Watch-DevKitLog.ps1 -Index 2`）。自動フリープレイも 1 つ目だけで行う

## セットアップ

1. `dotnet build` でビルドすると `$(AmongUs)\BepInEx\plugins` に配置される（ゲームを終了しておくこと）
2. `BepInEx/config/dev.nosdevkit.cfg` の `AddonSourceDir` に、`addon.meta` を含むフォルダを設定する
3. 結果は `BepInEx/LogOutput.log`（BepInEx のコンソール）に `HotReload:` で出る
